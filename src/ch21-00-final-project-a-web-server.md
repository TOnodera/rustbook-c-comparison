# 最後のプロジェクト：マルチスレッドのWebサーバを構築する

長い旅でしたが、ついに本書の終わりへたどり着きました。この章では、最後の数章で取り上げた概念の一部を実践し、それ以前に学んだ内容も振り返るため、もう一つのプロジェクトを一緒に作ります。

最後のプロジェクトでは、「hello」と表示するWebサーバを作ります。Webブラウザでは図21-1のように表示されます。

![hello from rust](img/trpl21-01.png)

Webサーバは次の手順で構築します。

1. TCPとHTTPについて少し学ぶ。
2. ソケットでTCP接続をリッスンする。
3. 少量のHTTPリクエストを構文解析する。
4. 適切なHTTPレスポンスを生成する。
5. スレッドプールでサーバのスループットを強化する。

ただし、始める前に一つ断っておきます。ここで使う方法は、RustでWebサーバを構築する最善の方法ではありません。これから作るものよりも完全なWebサーバやスレッドプールの実装を提供する、本番利用可能なクレートが[crates.io](https://crates.io/)には数多くあります。

この章の目的は、手軽な方法を選ぶことではなく、仕組みを学ぶことです。Rustはシステムプログラミング言語なので、扱う抽象化の水準を選び、ほかの言語では難しかったり実用的でなかったりする低い層まで降りられます。将来利用するかもしれないクレートの背後にある一般的な考え方と技術を学べるよう、基本的なHTTPサーバとスレッドプールを手作業で実装します。

> **C言語との比較**
>
> CでもソケットAPIとスレッドを使って同様のWebサーバを実装できますが、接続やバッファの寿命、スレッド間で共有するデータ、終了時の後片付けをプログラマ自身が慎重に管理します。この章では、Rustの所有権、型、チャネル、`Drop`が、同じ低レベルの仕組みを扱う際にどこで安全性を支えるのかを一つのプロジェクトで確認できます。
